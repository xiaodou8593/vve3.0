# 着色器接口

`vve:shader` 通过特定颜色的 `entity_effect` 粒子向 ShaderSelector V4
传递控制数据。数据包负责计算粒子的 ARGB 颜色，资源包中的核心粒子着色器
识别标记颜色，再由后处理着色器读取持久化数据通道。

它不是数据包内部的 GLSL 着色器，而是 VVE 对 ShaderSelector 粒子通信协议
的封装。

数据包源码目录：

```text
data/vve/function/shader/
```

资源包中的对应接口由 `marker_settings.glsl`、`data.fsh` 和最终后处理
`shader.fsh` 共同定义。数据包端的颜色基值必须与
`marker_settings.glsl` 中的 marker 定义保持一致。

## 1. 初始化

`vve:shader/init` 由 `vve:_init` 调用，创建或初始化以下临时记分板对象和
常量：

```text
angle、stemp、color
-1、64、360、256、1024、10000
roll_packet_high_base、roll_packet_low_base
fakefov_instant_base、fakefov_linear_base
```

其中：

| 对象 | 用途 |
|---|---|
| `angle` | 兼容旧角度接口的临时输入 |
| `stemp` | 通用整数临时变量 |
| `color` | 即将写入 `storage vve:shader color` 的完整 ARGB 整数 |
| `-1`、`360`、`256` | 符号处理、角度归一化和字节运算常量 |
| `64`、`1024`、`10000` | 旧的“10位角度＋6位速度”数据包协议所用常量，当前16位纯角度协议不再依赖 |
| `roll_packet_high_base` | 滚转角高字节 marker 的 ARGB 基值 |
| `roll_packet_low_base` | 滚转角低字节 marker 的 ARGB 基值 |
| `fakefov_instant_base` | FakeFOV 立即设置 marker 的 ARGB 基值 |
| `fakefov_linear_base` | FakeFOV 插值设置 marker 的 ARGB 基值 |

`*_base` 只表示蓝色通道为 `0` 时的粒子 ARGB 基值。使用时把 `0..255`
的目标数据加到基值上，即可得到最终颜色：

```mcfunction
scoreboard players operation color int = roll_packet_high_base int
scoreboard players operation color int += angle_high int
```

需要特别注意：常量名称本身不决定插值操作。真正的通道、操作类型和插值
参数由资源包中的 `marker_settings.glsl` 决定。例如，同一个颜色基值在
marker 被定义为 `op=0` 时表示立即设置，被定义为 `op=4` 时则表示循环
加速插值。

同一版本中不得为完全相同的 marker 颜色签名同时注册两种操作。

## 2. 底层粒子发送接口

### 2.1 `vve:shader/roll_instant`

函数从 `storage vve:shader color` 读取已经组装完成的颜色，并在当前执行
位置生成控制粒子：

```mcfunction
data modify storage vve:shader color set value -67175413
execute at @s run function vve:shader/roll_instant with storage vve:shader
```

宏展开后的核心命令等价于：

```mcfunction
particle entity_effect{color:<color>} ^ ^ ^
```

### 2.2 `vve:shader/roll_linear`

`roll_linear` 的输入形式相同：

```mcfunction
execute store result storage vve:shader color int 1 run scoreboard players get color int
execute at @s run function vve:shader/roll_linear with storage vve:shader
```

这两个函数都是底层粒子发送封装。函数名称用于区分历史调用路径，但控制
粒子最终执行立即设置、恒速插值、循环插值还是加速插值，仍取决于颜色所
匹配的 marker 定义，而不是取决于调用的是 `roll_instant` 还是
`roll_linear`。

调用任一函数前，都必须先保证：

```text
storage vve:shader color
```

中存在有效的32位有符号 ARGB 颜色整数。

## 3. 当前滚转角接口

### 3.1 输入

当前双通道16位角度版本直接读取物理系统中的：

```text
psi int
```

`psi` 的单位为：

```text
度 × 10000
```

例如：

| 滚转角 | `psi int` |
|---:|---:|
| `0°` | `0` |
| `45°` | `450000` |
| `90°` | `900000` |
| `180°` | `1800000` |
| `-90°` | `-900000` |

当前版本直接使用 `psi` 的方向和精度，不再执行：

```mcfunction
scoreboard players operation angle int = psi int
scoreboard players operation angle int *= -1 int
scoreboard players operation angle int /= 10000 int
```

也就是说，滚转角不取反，并且不会先截断为整数度。

### 3.2 `vve:shader/roll_linear_from_angle`

`vve:shader/roll_linear_from_angle` 是当前的高层滚转更新入口。调用示例：

```mcfunction
execute as @a[tag=tmp,limit=1] at @s run function vve:shader/roll_linear_from_angle
```

函数执行以下处理：

1. 将 `psi` 归一化到一整圈范围；
2. 将一整圈映射到 `0..65535`；
3. 将16位角度拆分为高字节和低字节；
4. 使用 `roll_packet_high_base + angle_high` 生成高字节 marker；
5. 使用 `roll_packet_low_base + angle_low` 生成低字节 marker；
6. 将两个颜色依次写入 `storage vve:shader color`；
7. 分别发送高字节和低字节控制粒子；
8. 按需发送 FakeFOV 控制粒子。

16位角度的理论分辨率为：

```text
360 / 65536 = 0.0054931640625°
```

高位通道和低位通道都是角度映射的一部分，不再在低6位中保存速度档位。
`angular_z` 仍可由物理系统用于动力学计算，但当前纯角度粒子协议不再把它
打包进这两个通道。

### 3.3 高低字节的读取约定

当前资源包约定：

- 高位通道使用循环操作，目标蓝色按 `blue / 256` 写入；
- 低位通道使用非循环操作，目标蓝色按 `blue / 255` 写入；
- 后处理着色器直接读取两个通道正在插值的浮点输出；
- 着色器不得先对通道输出执行 `round()`，否则会重新产生离散跳变。

后处理端等价的组合方式为：

```glsl
float highPart = fract(
    readChannel(VVE_ROLL_ANGLE_HIGH_CHANNEL)
);

float lowByte = clamp(
    readChannel(VVE_ROLL_ANGLE_LOW_CHANNEL),
    0.0,
    1.0
) * 255.0;

float rotation = fract(
    highPart + lowByte / 65536.0
);
```

### 3.4 `vve:shader/roll_instant_from_angle`

旧版 `roll_instant_from_angle` 只面向单通道8位角度协议。当前初始化中已经
不再提供旧的单通道 `instant_base`，因此该函数不应继续作为当前滚转接口
调用。

如果需要真正的“双通道立即设置”，必须在 `marker_settings.glsl` 中为高、
低字节分别注册额外且不冲突的 instant marker，并为它们增加独立颜色基值。
仅把函数名改为 `roll_instant`，不会改变现有 marker 的插值操作。

## 4. FakeFOV 接口

FakeFOV 使用一个 `0..255` 的蓝色通道值：

```text
0   = 不进行额外安全裁切
255 = 完整启用任意滚转角安全裁切
```

### 4.1 立即设置

```mcfunction
scoreboard players operation color int = fakefov_instant_base int
scoreboard players add color int 255
execute store result storage vve:shader color int 1 run scoreboard players get color int
execute at @s run function vve:shader/roll_linear with storage vve:shader
```

虽然示例通过 `roll_linear` 发送粒子，但实际操作由
`fakefov_instant_base` 对应的 instant marker 决定，因此仍然是立即设置。

### 4.2 插值设置

```mcfunction
scoreboard players operation color int = fakefov_linear_base int
scoreboard players add color int 255
execute store result storage vve:shader color int 1 run scoreboard players get color int
execute at @s run function vve:shader/roll_linear with storage vve:shader
```

此时颜色匹配 FakeFOV 的插值 marker，通道输出会按照
`marker_settings.glsl` 中配置的操作和速率向目标值移动。

## 5. 测试接口

`vve:shader/test_roll_15` 是固定颜色测试函数。它只生成一个写死颜色值的
粒子，不读取 `psi`、`angle` 或 `storage`。

该函数适合检查：

- 粒子是否成功生成；
- 玩家是否能够看到 marker；
- 资源包是否能够识别 marker；
- 后处理管线是否正在运行。

它不适合验证16位角度拆包、插值方向或物理系统与滚转画面的同步。

## 6. 使用约束

1. 所有底层绘制函数都使用当前执行位置的局部坐标 `^ ^ ^`。
2. 调用函数时必须保证执行位置对应需要接收控制粒子的玩家。
3. 颜色值必须是 Minecraft `entity_effect` 接受的32位有符号整数。
4. 数据包中的颜色基值必须与资源包 `marker_settings.glsl` 完全一致。
5. `angle`、`color` 和 `stemp` 是共享临时对象，不能在同一调用链中嵌套使用。
6. `psi` 由物理系统维护，着色器接口只读取它，不修改物理实体状态。
7. 着色器接口只负责生成控制粒子，不负责物理更新或持续调度。
8. 同一套高低字节必须使用同一版本的 `marker_settings.glsl`、
   `shader.fsh` 和 `.mcfunction`，不得跨版本混用。
9. 原版 `data.fsh` 对加速通道速度存在上限；仅提高低位加速度不能无限提高
   低位跟随速度，最终参数需要在游戏内验证。
10. 不应为此接口删除或重排已经能够工作的 `transparency.json`、
    `swap`、`swap2` 或模糊处理管线。

## 7. 旧协议说明

初始化中保留的 `64`、`1024` 和 `10000` 来自上一版16位数据包协议：

```text
高10位：角度锚点
低6位：带符号速度状态
```

该版本由着色器读取数据通道的更新时间并进行实时外推。由于高、低字节的
更新时间和数据包变化难以稳定同步，实际测试中出现了明显抖动。

当前双通道版本改为：

```text
高8位：角度高字节
低8位：角度低字节
```

因此当前滚转接口不再读取低6位速度状态，也不再依赖 shader 端的
`getRollRate()`、`highAge`、`lowAge` 或 `elapsed` 外推逻辑。
